> 负责：陈奕霖（成员 B）　日期：2026-11-27
> 对应任务书：2.2 周计划第 10 周「画像模块技术选型验证（pyBKT 跑通样例数据）」；4.3「课程画像：掌握概率来自学习事件累计、pyBKT」。

## 结论

**pyBKT 能跑通，用来离线拟合参数；学生电脑上不装。**学生本机用 BKT 的逐题更新公式（十几行纯 Python）加课程级参数算掌握概率，和 pyBKT 算出的结果**完全一致**（逐题对比最大差 0）。

这样定有两个原因：

1. **本机也用不上拟合。**拟合参数要几十个学生的作答序列，学生电脑上只有他自己一个人的数据。本机要做的只是“参数已知，来一题更新一次”。
2. **pyBKT 和新版依赖不兼容。**在 Python 3.14 上要把 scikit-learn 锁在 1.7.2、numpy 锁在 2.3.5，还要关掉多进程并行，否则一导入或一拟合就报错。学生端和 Hermes 共用 3.14 环境，为一个公式背上这些版本锁和约 180 MB 的 numpy / pandas / scipy / scikit-learn 不值得。

## 怎么测的

不下载外部数据集，按我们自己的契约造模拟数据：

1. 给 8 个知识点各设一组“真实参数”（先验、学会率、蒙对率、失误率），模拟 60 个学生作答，共 5554 条学习事件（含 718 条提问），**每条都过 `events.schema.json` 校验**。
2. 按契约⑭ `profile-rules.yaml` 的口径转成 pyBKT 输入：只取有效作答；独立做对记“对”，提示后做对和部分正确记“错”；提问不计。共 4836 行。
3. 用 pyBKT 拟合，把拟合参数和真实参数对照；再挑一个学生，用拟合参数逐题手算，和 pyBKT 的预测对照。

## 结果（2026-11-27）

| 问题 | 结果 |
|---|---|
| 能否在 Python 3.14 上跑通 | 能，pyBKT 1.4.3 是纯 Python 包，不用编译；但要做下一节的三处处理 |
| 拟合准不准 | 训练集 AUC 0.853；32 个参数平均误差 0.043，最大 0.21（KP-RAG-001 的先验 0.40 拟合成 0.19）。蒙对率普遍拟合偏低，因为“提示后做对”按口径记错，部分蒙对被算成了错，符合预期 |
| 本机公式和 pyBKT 一致吗 | **一致**：同一学生同一知识点逐题对比，最大差 0.000000 |
| 耗时 | 拟合 4.2 s（单进程，8 个知识点各 5 次随机重启）；预测 0.13 s；本机逐题更新约 0.2 ms/次 |
| 末态判断对不对 | 掌握概率 ≥ 0.95 的 353 个（学生 × 知识点）里 352 个确实已掌握；< 0.6 的 91 个里有 19 个其实已掌握。作答次数少时偏保守，由“待确认 + 追问”兜底 |

|---|---|---|---|---|
| 1 | ✓ | 0.056 | 0.480 | 待确认 |
| 2 | ✗ | 0.480 | 0.216 | 待确认 |

## 兼容问题与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `import pyBKT` 就报 `AttributeError` | pyBKT 导入时会把 scikit-learn 内部的评分函数逐个试调一遍，只捕获 `TypeError`；scikit-learn 1.8 起新增的内部函数抛的是 `AttributeError` | scikit-learn 锁 1.7.2（1.8.0、1.9.1 都不行） |
| 拟合报 `ValueError: setting an array element with a sequence` | pyBKT 的 EM 代码把一维数组当标量赋值，numpy 2.5 不再允许 | numpy 锁 2.3.5（2.5.5 不行，2.4 未测） |
| 拟合时 OpenBLAS 反复报内存分配失败 | pyBKT 默认多进程并行，每个进程各起一套数值库线程 | `Model(parallel=False)`，单进程 4 秒够用 |

pandas 3.1.1 无问题。完整版本见验证目录的 `requirements-lock.txt`。

## 对契约⑭的影响

契约⑭（`contracts/learner.sql`、`contracts/profile-rules.yaml`）按本结论定了这几条：

- 本机按公式逐题更新；`kp_state` 只存掌握概率，BKT 参数放在规则文件里，全班一致。
- 参数初值按知识点难度（入门 / 进阶 / 挑战）分三档，拟合后写进 `per_kp_params` 按知识点覆盖。
- **参数从哪来**：上报不含逐条事件（report.v0.2 的硬约束），教师端拿不到序列，没法拿全班数据拟合。试测时经学生同意导出样例事件，用 pyBKT 离线拟合后写回规则文件。
- pyBKT 的遗忘参数不用（`forgets: 0`），遗忘由规则文件里的半衰期模型单独算。

## 附：本机逐题更新

```python
def bkt_update(p, correct, learn, guess, slip):
    """p 是作答前的掌握概率；返回作答后（含本题学到的部分）的掌握概率。"""
    if correct:
        known = p * (1 - slip) / (p * (1 - slip) + (1 - p) * guess)
    else:
        known = p * slip / (p * slip + (1 - p) * (1 - guess))
    return known + (1 - known) * learn

# 第一次作答前 p = prior；之后每来一条有效作答更新一次
```
